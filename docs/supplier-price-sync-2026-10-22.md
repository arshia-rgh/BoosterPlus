# PRICESYNC174 — automatic supplier price synchronization

Owner request, 22 October 2026: each game's shop has PLAYORA's own manual products and supplier (Nexus) products. Imported supplier products are published either with the default markup (15%, configurable; a per-offer markup is also possible) or with an explicit overridden selling price. When the supplier changes its price and nobody edits ours, published prices go stale. Add a job that runs continuously every 8 hours and:

1. for published supplier products priced by markup (no override), applies the supplier's new cost automatically so the customer price is the new cost plus the markup;
2. for products published with an overridden price, never changes the price, and alerts administrators prominently at the top of Shop products — old/new supplier cost and our current price — with a way to acknowledge or adjust through the normal editor.

## Boundaries

- Catalog reads only. Supplier purchases stay disabled (`SUPPLIER_PURCHASES_ENABLED=false`), Vendoria absent, no live order, message, invoice or funds test.
- Published releases are immutable. Repricing creates a new release through the publication checks; accepted contracts, stored purchase snapshots, unpaid reservations and historical releases/bindings keep their own amounts.
- Never fabricate a price: unavailable/removed offers, changed delivery requirements, malformed or inconsistent quotes and API failures keep the last good release and record why.
- This supersedes, for markup-priced publications only, the earlier rule that a private price edit never changes a published listing ([shop suppliers](shop-suppliers-2026-10-19.md)). Explicit overrides, accepted orders and historical terms are unchanged.
- Focused checks and the senior rendered design gate; no full gate. A fresh exact recovery decision is required after the signed candidate and server preflight.

## Semantics

- **Schedule.** Every worker ticks once a minute and enqueues `supplier.price_sync` for the current window (`now` truncated to the interval) per configured Nexus connection. The durable queue's idempotency key `supplier-price-sync:<connection>:<window>` makes concurrent workers and restarts harmless; a missed window runs as soon as a worker is up. Default 8 hours; `SUPPLIER_PRICE_SYNC_INTERVAL` accepts whole minutes from 1h to 168h. No deployment configuration change is required.
- **Runs.** `supplier_price_runs` holds one row per connection and window (unique). Each job handles one bounded batch of 10 products in stable ID order, then saves the cursor and enqueues the next batch in the same transaction. A retried job takes over the run lease; late writes from an earlier attempt are fenced by the lease token.
- **Candidates.** Published or paused products whose current release has a supplier binding for the connection and the configured merchant.
- **Reads.** The existing fresh-quote adapter (`FreshQuote`/`QuoteOffer`, GET only) for the reviewed display quantity (1, or the offer's reviewed minimum), paced 250 ms apart with a 20 s limit each. Quotes must match connection, merchant, product, offer and quantity. A product with an unexpired, unconsumed checkout quote on its current release is deferred to the next window so that quote can still be accepted.
- **Markup products.** New price = `quote.CustomerPrice(publication markup)` — the same exact-decimal, single half-up cent rounding as checkout, using the markup stored in the published binding (later changes to the default markup do not reach existing publications). When the rounded price differs, a new release copies the current release with only the variant price changed, re-runs current publication validation, artwork, game, merchant and binding checks, and stores a new release binding whose offer cost is the new unit cost. An untouched draft (same binding and old price) receives the same price, so a later manual publish does not restore the stale one; drafts with other prepared changes are left alone. The product event `supplier_repriced` and audit `shop_product_supplier_repriced` use the system actor (`actor_id` empty, reference `system:supplier-price-sync`, run and from/to amounts in metadata). If any check fails the price is kept and the product is marked `needs_refresh`.
- **Override products.** Compared by supplier total for the display quantity against a baseline: the cost in the current release's binding, or the amount an administrator last acknowledged. A difference opens an `override_changed` alert; the release is never touched. Acknowledging keeps the selling price and makes the reviewed amount the new baseline, so only a further change alerts again. Republishing (a new release) restarts the baseline from that release.
- **Failures.** `unavailable` (alert after 2 consecutive checks), `requirements_changed` (immediately), `check_failed` (after 3), `needs_refresh` (immediately). Three or more failed reads before any success in a window are treated as a provider outage: the window fails with `supplier_unavailable` and no product is marked.
- **Records.** `supplier_price_reviews` keeps the latest check per product (status, attention open/acknowledged, totals, selling amount, failure count, last automatic reprice). Prices live only in releases.
- **Admin API.** `GET /api/v1/admin/shop/price-sync` (schedule, last run, open alerts ≤50 with total count, automatic updates from the last 7 days ≤20) and `POST /api/v1/admin/shop/price-sync/{id}/acknowledge {version}` (current administrator, exact version, audited `shop_product_price_acknowledged`). Product list rows add `price_status`, `price_attention` and recent `repriced_at`; the product draft adds `price_review`.

## Admin presentation

Shop products leads with a price-check section: "{n} price alerts" (amber accent) or a quiet "Supplier price checks" line with the schedule, last check and next check. Open alerts are ordered by severity; overridden products show "Supplier cost[ for N units]: USD old → USD new" beside "Your price", with an exact below-cost warning and "Keep my price" / "Change fixed price" (supplier catalog deep link `?q=<supplier product>`) / "Open product". Blocking problems (delivery requirements changed, needs refresh) cannot be dismissed. Automatic updates from the last 7 days sit in a collapsed list; product rows carry alert and "Price updated" badges; the product editor repeats an open alert above its toolbar or notes a recent automatic update. An independent senior designer decided the presentation (round 0, D1–D21) and passed it after three rendered rounds (round 1: six findings; round 2: one); see [the review record](redesign/reviews/PRICESYNC174_DESIGN.md).
