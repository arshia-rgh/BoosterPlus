No payment behavior or paid-state bypass is added.

## Increment B: native provider instructions — delivered

New checkouts create one deposit against their durable invoice and keep the result ambiguous until an authenticated payment read matches the invoice, attempt, commercial price, asset and network. An explicit migration29 separates new native attempts from historical hosted invoices. Both write claims persist before provider I/O; a retry, crash or lost response cannot make another claimed write. Native attempts never store or expose a hosted fallback link. Existing hosted attempts retain their original behavior.

The owned order projection includes exact crypto text, destination, a locally generated address-only QR, any provider memo, provider/local expiry and freshness deadlines. No external QR service receives the address. Missing/invalid instructions, wrong references, detected funds, expired windows, stale evidence and provider failures withhold payable instructions. Provider timestamps accept valid offsets. A two-minute display freshness limit is an engineering safeguard independent of the accepted commercial window. Reconnect waits for a new successful response; copying rechecks expiry and connection state. Creating instructions, copying and provider redirects never mark an order paid. New checkout can pause while existing evidence still reconciles.

Official public API references used: [NOWPayments API](https://nowpayments.io/api) and its [linked provider collection](https://documenter.getpostman.com/view/7907941/2s93JusNJt). The invoice-payment adapter sends only invoice ID and the accepted asset; it does not send customer email or payout overrides. Authenticated GET retains strict invoice identity requirements. Real provider response/asset qualification and actual funds movement remain separately held R11 work; no live merchant requests were made here.

Initial native TiDB race tests passed: simultaneous issuance, lost-response discovery, private projections, failed reads/freshness, paused reconciliation through settlement, crash claims, unclaimed recovery and explicit migration upgrade/rollback/drift. Component tests cover exact decimals, memo, clipboard denial/late expiry, unsafe QR/address inputs, offset timestamps and reconnect barriers. The first browser run found valid offset timestamps being rejected; the parser was fixed without relaxing destination or payment evidence checks. Current browser rerun and scoped senior design review are in progress; the unchanged full hook and push remain required. These initial checks do not complete DI05.
