## Fix/review rounds

The first design round identified an inherited narrow administrator layout, duplicate sign-in introduction/nested cards, joined mobile headline words, unequal Google/email actions and moving explorer controls. These were corrected in shared sign-in layout and the service explorer. The next rendered round found no remaining actionable visual findings across desktop, tablet and narrow phone layouts, including selector keyboard/wrap/navigation and OS reduced motion.

The form review found focus theft during correction, unchanged unknown-error arrays, native validation bypassing persistent inline messages, missing registered action/confirmation controls, protected-answer editor focus, and custom-order rejections losing the correct stage. The implementation now retains values and exact unknown-delivery retries, focuses enabled invalid fields in page order, exposes record-level failures, and preserves errors across the correct custom-order stage. Definitive chat-form rejection resets the expiry/request key; uncertain delivery retains the original payload. A final F159-15 fix records unknown-summary focus only after its scheduled frame executes, so remounting editor fields cannot cancel the only focus attempt. Regression tests cover these paths.

The final parity review caught native WebKit selects rendering at23px despite min-height. A scoped explicit48px height preserves the native arrow and usable touch target. Chromium/WebKit desktop/phone final captures confirm48px without overflow. Equivalent built-host regression coverage remains maintained.
