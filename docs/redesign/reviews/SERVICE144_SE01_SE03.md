## Limits and retained failures

- Fixtures qualify rendered behavior, not real backend authorization, email delivery, Google authentication, provider acceptance, payment success, database persistence or production deployment. Google provider entry is disabled in the harness; only its returned staff-access message was rendered. Resend time was advanced with the browser clock.
- Hosted provider navigation was blocked before reaching the provider. Synthetic support conversation creation did not send a message. No real accounts, mail, invoices or funds were used.
- Chromium/WebKit responsive emulation is not a physical-device, browser-extension or screen-reader audit. No claim of all possible user flows is made.
- Original failed review attempts remain in the evidence: an incorrect seller route, an unmodelled synthetic conversation request, a CSP-blocked text-resize helper, a collapsed-editor helper, and a draft-save fixture that initially failed to account for the editor resetting `reviewed=false`. Corrected helpers used the actual routes/contracts. The original generic mapping banner came from a wrong synthetic error code, later corrected to `catalog_invalid`. These fixture mistakes are not application failures or passed cases.
- Parent-run backend/security/build results and the complete repository gate remain separate release evidence. This review does not authorize deployment, change production settings, or waive outstanding checks.
