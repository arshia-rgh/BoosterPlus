# Panels140 customer and seller exploratory review

Date: 8 October 2026. Reviewer: independent customer/seller tester, with findings independently triaged by the senior UI/UX reviewer. Application source was read only. This report is a bounded manual UI review, not an assertion that every possible journey or production integration passed.

The actual built React application was exercised through navigation, typing, selecting, back/forward, local sections, validation, explicit API failure and retry. Synthetic API responses were authored from the application schemas, backend error codes and existing test contracts. No live accounts, email, Google authentication, provider request, invoice or funds movement was used.

## Fixture corrections and failed attempts

The initial preview's audience check wrongly rejected missing portal headers on fixed customer routes. Parent corrected only the private harness and reran its tests; baseline application source stayed immutable. That initial403 is not a product defect. Additional test setup corrections included exact query/path matching, `null`/204 command responses instead of `{ok:true}`, explicit conversation UUIDs, sequential estimate/order bodies and waiting for an already displayed item before switching its response to removed state. Unknown501, body409 and selector timeouts remain in journals and interrupted traces.

`payment-round1`, `games-news`, `wr-signin-draft`, `support-seller` and `account-breadth` have interrupted attempts. Their completed replacement bundles are `payment-round2`, `games-news-round2`, `wr-signin-draft-round2`, `chat-deep-round1`/`seller-review-round1`, and `account-breadth-round2`. The case bundle's final review-selector interruption is superseded only for review coverage by `purchase-review`; its first two case checkpoints remain valid. This separation avoids converting setup failures into UX findings or silently declaring interrupted paths complete.
