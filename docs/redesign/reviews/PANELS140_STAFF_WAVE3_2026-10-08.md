## Setup corrections, kept separate from application findings

- Some first attempts used wrong literal control names or forgot that a wrapping label's accessible name includes options. These yielded bounded locator stops, then were corrected from the real DOM. No product edit was made to satisfy a selector.
- An initial composer fixture omitted exact `after=2` polling. Its501 correctly hid stale messages and disabled editing. The completed rerun includes exact polling/read responses for each sequence and displays both submitted messages; the missing requests remain in the journal.
- The first co-play exploration used dates that were already past. Its confirmation observation is not used as a valid scheduling case. The final run fixes browser time before confirming, then advances it past end for no-show, and reloads because the assignment has no guessed “Refresh sessions” button. A later future proposal is explicitly seeded for cancellation.
- Review helper reruns replace same-name DOM/trace/screenshots with the final attempt. The append-only request journal and interrupted screenshots retain setup history, but every earlier trace is not independently preserved. Final completed states, rather than aborted helper attempts, underpin the matrix.
- Unknown501s, missing fixtures and request-body mismatches are never substituted for authored403/409/503 branches. Fixture response changes are setup, not backend state transitions.
