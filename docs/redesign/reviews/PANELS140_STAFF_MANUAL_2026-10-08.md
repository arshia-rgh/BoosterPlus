## Harness corrections and limits

The first preview bind was sandbox-blocked and its partial `admin-round1` evidence directory was retained; `staff-round1` then started with the authorized localhost bind. Sparse initial seed routes omitted exact query combinations; these returned explicit501 and were extended using the current schemas. They are setup gaps, not service outages. An early long screenshot/control wait was terminated only for this review process; the full server gate and shared preview source were untouched. Subsequent waits were bounded. Selector ambiguity between hidden catalog sections and global versus record Overview links was corrected with explicit section/record selectors; this was test setup, not an application defect.

The first publication fixture returned revision2 while its reload still returned revision1, creating stale-version wording. This was an incoherent fixture, corrected for the WebKit publication round by updating the matching GET response before the synthetic POST. Only the coherent round supports normal publication display. Initial scripts that stopped on ambiguous/wrong selectors retain their evidence and are not counted as completed runs.

Physical devices/keyboards, assistive technology, real zoom, actual staff authority/session isolation, provider/Google/email integration, durable writes and concurrent transaction behavior remain beyond these isolated manual checks. The full server gate independently qualifies its frozen source. Later UX changes need a new built snapshot and scoped round-trip evidence; this report does not certify those edits.
