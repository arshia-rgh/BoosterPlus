# SUPPLIER168 — Nexus and Vendoria shop integration

Owner-authorized on 19 October 2026. Start with Nexus Sandbox and Vendoria Test; retain PLAYORA's own manually fulfilled products. This supersedes the original manual-only shop scope for this integration. The wider UX165 audit remains paused.

## Accepted behavior

- Import the complete accessible catalog from each supplier into a private, searchable supplier library. Preserve supplier/game/category/product/form identifiers and availability. Import is separate from customer publication; do not silently discard unsupported or unavailable rows.
- Map supplier games and regions to PLAYORA catalogs. Show automatic ID delivery, account sign-in delivery (24–72 hours), code delivery, and manual products accurately. Group by game, delivery method, region and category. Unknown eligibility requires review; a display label does not override a supplier country restriction.
- Default markup is 15% of the supplier's USD cost. Administrators may change the markup or set an exact customer price per offer. Use decimal arithmetic and round the final USD customer amount once to cents, half up. Show supplier cost, markup/override and customer price together. Preserve explicit overrides during sync, and never rewrite accepted orders.
- Recheck availability and cost before checkout/dispatch. Customer payment is through the existing NOWPayments flow. Only a verified, allocated payment for the current accepted contract can authorize a supplier purchase. A browser redirect or supplier callback cannot mark an order paid.
- Own products keep their authored prices and manual fulfillment. No customer wallet or change to seller payouts is introduced.
- Store sensitive delivery inputs encrypted and keep them out of ordinary order snapshots, chat previews, logs and analytics. Nexus optional secrets can be entered on the supplier verification page instead of persisted. Vendoria's codes, prompts, game-exit requests and private delivered keys need explicit customer actions in the existing order workspace.
- Supplier delivery failure, cancellation, partial fulfillment, unavailable stock, insufficient merchant balance and changed prices have clear customer/staff states. Never silently buy a replacement or treat failure as success. Existing refund/case protections remain.

## Provider contracts and known differences

Authoritative sources: [Nexus](https://nexus.amadeustech.dev/docs/api.md), [Nexus Sandbox](https://nexus-sandbox.amadeustech.dev/docs/api.md), [Vendoria](https://vendoria.amadeustech.dev/docs/api.md), [Vendoria Test](https://vendoria-test.amadeustech.dev/docs/api.md). Public copies are cached privately under `.cache/suppliers/onboarding/` for implementation. Dashboard credentials are not API runtime credentials: only the full Shop token is needed for API requests and webhook HMAC verification.

- Both webhooks sign the **exact raw body** with HMAC-SHA256 using the full Shop token in the `Sign` header. Verify in constant time before parsing; bound payload size. Callbacks identify existing environment-bound attempts, not arbitrary customer orders. Reconcile authoritative order state; never trust a callback as payment evidence.
- Nexus supplies a complete catalog with encoded parent IDs, field types, quantity rules and optional region metadata. Sandbox reports `realMoney=false`. `maxTotalPrice` bounds a purchase. `externalId` deduplicates pending/completed orders, but a failed order releases it: a blind retry can purchase again. Persist one dispatch before network I/O and reconcile uncertainty without automatic resubmission.
- Vendoria has separate services/categories/forms/products; each product/form pair has its own fee-inclusive price. Bulk reads avoid rate-limit exhaustion. `shopOrderId` is described as a reference, not a guaranteed unique idempotency key. The documented create API has no maximum-price field. Do not claim a fresh read eliminates a price race or that timeouts are safe to retry. GameCore's owner-supplied response on 19 October confirms these documentation gaps against version 3.30.0: no binding quote/max-price input, no replay guarantee, no reference filter/direct lookup, no immediate-visibility guarantee, and no confirmed Test/production deployment parity. Terminal statuses are completed/cancelled, not failed. Production Vendoria purchasing remains disabled; test implementation exercises a locally fenced single submission and unresolved reconciliation without another POST. A fresh price read only reduces the price-change risk. Cancellation is not an immediate financial rollback.
- Both APIs may deliver codes; Nexus also includes credential-based products. Delivery classification uses reviewed product/form data, never the provider name alone. Vendoria fields may include images and regex rules; do not execute supplier HTML/scripts or an unsafe regex in a browser.
- Supplier status changes and interactive requests are distinct. In particular, repeated game-exit requests can be legitimate; collapse immediate transport duplicates without permanently suppressing later requests.
