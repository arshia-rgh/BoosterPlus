# Operational delivery forecasts

SQL migration 15 adds the optional saved forecast to paid fulfillment records. Ent generates queries; the explicit Cobra migration command owns schema changes. Accepted order contracts, prices and quoted delivery hours remain immutable.

An administrator can declare an optional delivery policy on each service. It is published and purchased with the immutable catalog release. The policy contains an IANA operating zone, 1–28 weekly opening windows, up to 180 local closure dates and 1–40 ordered rules. Windows cannot overlap; overnight work is split at midnight, with `24:00` permitted only as a closing boundary. Configuration is public catalog data, not a place for internal costs or private staffing information.

Each rule has an explicit fulfillment mode, optional bounded typed conditions on ordinary prepayment form fields, a minimum/maximum work duration, a minimum/maximum queue delay and queue minutes per other active paid assignment. The first matching rule within the mode wins. An unconditional rule must be last for that mode. Region and priority are ordinary administrator-declared choices; no field label has special executable meaning. Rules cannot reference later-stage or attachment fields. Missing rules never invent durations.

Durations use actual working minutes. Queue delay and its workload adjustment consume the declared operating calendar. Account-mode work then consumes that calendar; play-together work consumes only the order's currently confirmed sessions with its current assignee. Proposals and unbooked availability cannot create a completion promise. The calculator is bounded to 90 days, 100 other paid active assignments and 20 future confirmed sessions. Exhausted time, clock gaps at required boundaries or unsupported inputs return a review requirement rather than a partial optimistic range.

Daylight-saving arithmetic uses UTC instants resolved from local calendar boundaries. Repeated openings select the first occurrence and repeated closings the second, consuming the actual elapsed working minutes. Non-hour changes are supported. If distinct local windows overlap in UTC during a repeated hour, their union is consumed so each real minute counts once. Closure dates use the configured local zone. Tests cover weekends, closures, exact closing instants, midnight, repeated hours, skipped hours, invalid or overlapping declarations and insufficient confirmed time.

An admin explicitly requests a preview for queued, unstarted work after required ordinary handoff information is complete. Active staff authority and settled current-contract ownership are rechecked. Forecasting does not infer remaining effort from a progress percentage or silently resume held work. Other execution states require staff review and the existing manual timestamp override. Continued availability and any required temporary game access remain conditions of execution.

Preview application requires a reason, recent primary authentication and recent authenticator verification, observed work/order revisions, the original calculation instant and a matching basis digest. It recomputes within the identity transaction fence and rejects expired previews (ten minutes), changed workload, booking/assignment changes and tampered results. Concurrent applications produce one successful revision. The range, execution update, audit, customer timeline and notification enqueue commit atomically. Timeline copy retains all four UTC boundaries, the operating zone and rule key for historical review. An audit failure rolls everything back.

Customer and assigned-booster responses show separate earliest/latest start and finish windows. They omit other customers' identities, order IDs and workload counts. GET does not move dates. Any later execution revision, change to the active paid queue count or loss of staff eligibility marks the saved range for review while retaining it for reference. This deliberately conservative behavior can also flag an ordinary execution update. Staff explicitly recalculate or provide a reasoned manual override; a manual override clears the calculated range. There is no automatic repricing, deadline extension or financial effect.

All routes retain shared authentication, role, origin/CSRF, body-size and rate protections. The UI disables actions while refreshing and discards rejected previews. The admin editor leaves new duration fields unset/zero until staff declare valid values; no live Mobile Legends turnaround, price, win-rate promise or business calendar is seeded.

This stage does not resolve no-show fees, cancellation/dispute remedies, payment verification, seller settlement, or production qualification. Those remain explicitly tracked dependencies and later implementation work.
